# Django 4.2 Support Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Python 3.12/3.13 × Django 4.2 join the test matrix (package suites and example), as in django-crud-views.

**Architecture:** One vendored crispy template set; the theme accepts the template-identical crispy-bootstrap5
releases 2026.3 and 2026.9. Django-version gaps live in the example and the test settings, never in the package.

**Tech Stack:** Django 4.2/5.2/6.1, crispy-bootstrap5 2026.3/2026.9, nox, pytest-django.

**Spec:** `superpowers/specs/2026-11-19-django-4.2-support-design.md`

## Global Constraints

- Matrix: Python 3.12–3.15 × Django 4.2, 5.2, 6.1; Django 4.2 skipped on Python 3.14 and 3.15.
- `django>=4.2`, `crispy-bootstrap5>=2026.3`; nox installs crispy-bootstrap5 `==2026.3` on Django 4.2, `==2026.9` otherwise.
- `CRISPY_BOOTSTRAP5_VERSION` stays `"2026.9"`; new `CRISPY_BOOTSTRAP5_COMPATIBLE = ("2026.3", "2026.9")`.
- No migration changes; no change to package behaviour; nothing new in `src/` except `vendored.py`.
- RED on Django 4.2 is shown in a throwaway 4.2 environment (or the nox 4.2 session once Task 3 exists); GREEN on both
  4.2 and 6.1.

## Review Focus

1. **Anonymous requests on Django 4.2** reach a page: the stand-in must redirect like Django 5.1's middleware.
   Task 2's tests run the stand-in on every Django version.
2. **The login page itself redirecting to login** (an endless loop) on 4.2. Task 2 tests `/accounts/login/` → 200.
3. **Static files and the logout POST** behind the stand-in. Django's `LoginView`/`LogoutView` are marked
   `login_required = False` in 5.1+ only; on 4.2 the stand-in must exempt the login and logout URLs itself, plus
   `STATIC_URL`. Tested in Task 2.
4. **A future crispy-bootstrap5 release** accepted silently: only the two listed versions pass the version test;
   parity still byte-compares templates.
5. **Migrations generated by `.choices`** differ on 6.1: Task 1 runs `makemigrations --check` on 6.1 and 4.2.
