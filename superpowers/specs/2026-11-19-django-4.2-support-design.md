# Django 4.2 support: design (short)

Date: 2026-11-19. Size: a small change.

## Intent

django-crud-views supports Django 4.2; the theme should not be the reason a crud-views project on 4.2 cannot use
Tabler. Django 4.2 was dropped in the packaging design (2026-11-19) because crispy-bootstrap5 2026.9 and
django-crispy-forms 2.7 require Django >=5.2. That reason does not hold: crispy-bootstrap5 **2026.3** (the newest
release installable on 4.2, with django-crispy-forms 2.5) has templates and Python code byte-identical to 2026.9, the
release the pack is vendored from.

Goal: Python 3.12, 3.13 × Django 4.2 join the matrix (example on those rows too), as in django-crud-views (4.2 is
skipped on Python 3.14+). Non-goal: a second vendored template set, a public login-required backport in the package.
Note: Django 4.2's security support ended April 2026.

## Evidence (spike, 2026-11-19, throwaway copy)

Django 4.2.30, Python 3.12, crispy-forms 2.5, crispy-bootstrap5 2026.3, crud-views GitHub main: every other dependency
resolves. `tests/django_tabler` 33/33; theme suite 97/97 once a login middleware exists; crispy suite fails only the
version-equality test; example 259/260 after the fixes below, system check and `makemigrations --check` clean. The
`Enum.choices` change leaves 6.1 migrations unchanged ("No changes detected").

## Approaches

- **Chosen: one template set, accept the template-identical crispy-bootstrap5 releases.** Small fixes in the example
  and tests; nox pins crispy-bootstrap5 2026.3 on Django 4.2.
- Vendor a second template set from an older crispy-bootstrap5 and switch by version: not needed, the templates match.
- Keep 4.2 out: the theme would block crud-views projects on 4.2 for no technical reason.

## Design

1. **Example models**: the six fields with `choices=<Enum class>` (Django 5.0+) use `choices=<Enum>.choices`:
   `catalog.Beans.process`, `Beans.roast_level`, `Subscription.interval`, `Subscription.bag_size`,
   `roastery.GreenLot.process`, `RoastBatch.profile`. No migration changes.
2. **Login-required on Django < 5.1**: `django.contrib.auth.middleware.LoginRequiredMiddleware` exists from 5.1. The
   example (`example/config/settings.py`) and the theme test settings (`tests/crud_views_tabler/settings.py`) select it
   on Django >= 5.1 and a small stand-in otherwise: same behaviour (anonymous requests redirect to `LOGIN_URL`;
   views marked `login_required = False`, i.e. Django's `login_not_required` / `LoginView`, stay open). The stand-in
   lives with the example and with the tests, not in the package.
3. **Crispy version check**: `django_tabler.crispy.vendored` keeps `CRISPY_BOOTSTRAP5_VERSION = "2026.9"` (provenance,
   vendoring script) and adds `CRISPY_BOOTSTRAP5_COMPATIBLE = ("2026.3", "2026.9")`, the releases whose templates are
   byte-identical; the version test accepts any of them. `test_pack_parity.py`'s byte comparison is unchanged.
4. **Example test** `test_invalid_order_line_keeps_compact_row_and_error` asserts `aria-invalid="true"` (added by
   Django 5.0) only on Django >= 5.0.
5. **Requirements**: `django>=4.2`, `crispy-bootstrap5>=2026.3`; classifiers add Django 4 / 4.2. The `test` extra's
   exact crispy-bootstrap5 pin moves into nox: 2026.3 on Django 4.2, 2026.9 otherwise.
6. **Matrix**: `DJANGO_VERSIONS = ["4.2", "5.2", "6.1"]`, 4.2 skipped on Python 3.14/3.15 (as upstream); tests.yml and
   publish.yml run the 4.2 sessions per row (nox reports a skip as success). Docs, README, CHANGELOG, CLAUDE.md name
   Django 4.2, 5.2 and 6.1.

## Left to the builder

The stand-in middleware's exact code and where it sits (one module per settings user, or a shared test helper); how
the version is selected in settings; test layout for the stand-in.
